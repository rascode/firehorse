# Changelog

## Unreleased

- **Composition in the Index: layers, slots and nested markers** (`schema/composition.json`, `schema/composition.schema.json`, `scripts/composition.mjs`, `scripts/gen-index.mjs`, `scripts/fh-tag.mjs`, `sections.json`, `site/pages/**`, `test/composition.test.mjs`, relay FC1, Helm idea #210, 2026-11-18). The Index now says what every component is made of. `schema/composition.json` gives each of the 145 families its layer (token, part, field, composite, section, template; a child never outranks its parent and a field never holds a field), whether it is transparent (layout primitives and the text fold pass their children through), the 36 slot keys and the slots of the 76 families whose specimens fill them (key, the BEM element when it differs, order, one or many, required, the field type it binds and its display context, the families it accepts and its default). Every child component in a docs demo now carries `data-fh` with its most specific ID, and every element that fills a slot carries `data-fh-slot` (1,972 and 2,495 attributes on 18 pages; no class, markup or look changed). Both index files carry `layer`, `transparent`, `slots` and `compositions` (parent, child, slot, order, source `specimen`) per family; `agent/index.md` shows each family's layer and slots. `gen-index.mjs` fails the build on rules M1 to M7: an unmarked component root, an ID that is not in the Index (`local:` is refused here), a child with no slot or an undeclared one, an empty required slot, a layer break (six known pairs are listed under `layerExceptions` until they are ruled), a slot on a layout element, and a public FireKit view that names a class or code with no `/// fh:` line. `sections.json` slot lists now reference these slots, their prose kept per slot. The owners map no longer gives a class to a word of a family's name that no demo uses: `fh-row` (the Helm iOS row) is nobody's, and 54 such phantom names (`fh-the`, `fh-word`…) leave the map.
