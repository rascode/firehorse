# Changelog

## 1.1.0 — 2026-11-04

- **Table of contents** (`src/components/navigation/toc.css`): the label starts where the entries' text starts, past the rule and marker, not on the rule.
- **Docs site frame audit:** text standing beside a framed block starts where the block's text starts: the home adapt copy and its table, a label captioning a table (Theming), notes under demos (Data). The Stable's reading column is 40rem.
- **Gauge** (GAU, `src/admin/gauge.css`): now a full circle with the figure in the middle and the caption under it, and the indicator has rounded ends (drawn with `sin()`/`cos()` from `--fh-value`). The gauge is a size container, so the figure and the ends scale with `--fh-gauge-size` (now 8rem).
- **Metric tiles** (MET, `src/admin/metric.css`): one anatomy for every tile. Each part has a fixed row (title, description, gap, figure, chart/progress/people, source, detail); tiles in `fh-metrics` share the rows (subgrid), so figures sit on one line across a row and sources line up. Bold title, medium h3 figure on the bottom of its row, spacing by relationship. A gauge or ring is the figure of its tile. `fh-metric--spread` is now the same tile with the wide gap (48px). MET-1 demos put the description under the title.
- **Key value list** (KVL, `src/components/content/key-value.css`): each row is a size container; a row narrower than 18rem puts the value under its label, flush left, and lets long labels wrap. The same list at full width keeps label left, value right (the Open invoices tile on /admin/ collapsed vs full).
- **Docs site:** the offset panel starts at the footer again on every page (the footer's class gained `fh-footer--panel`, so the start marker stopped being added and the panel's dashed edges ran the full page height). Guidelines rule lists wrap each description so inline code stays in its line.
- **Cursor** (`src/tokens/config.css`, `src/base/reset.css`): the pointer is a white circle with a thin etch (a dark ring for light surfaces, a faint light ring for dark ones). Actions (links, buttons, summaries, checkboxes) get a slightly larger circle; text fields keep the text caret; disabled keeps not-allowed. Tokens `--fh-cursor` and `--fh-cursor-action`; `data-fh-cursor="system"` restores the platform arrow and hand. Every component `cursor: pointer` now reads `--fh-cursor-action`.

First public release.

- **Section card (SEC) and metric tiles (MET)** in Admin, and the **key value list (KVL)** in Content. Section card (`src/admin/section-card.css`): one area of a record, with a head (`__title` with a tone-tinted icon, `__tools` for chips or buttons on the right), `__lede`, `__subhead` (mono caps on a dashed rule), `__note` and a `__foot` for its actions; `--inset` is a frosted sub-card inside another (one address role), clouded by `--fh-frost`, `--aside` puts the lede beside the title on wide slots; knobs `--fh-section-card-pad`, `--fh-section-card-gap`. Metric tiles (`src/admin/metric.css`): `fh-metrics` lays out `fh-metric` tiles as many across as fit (`--fh-metrics-min`, 12rem), each with `__label` (icon), `__value` (figure font), `__sub`, `__source` and an optional `fh-progress`; `--needed` marks a fact still to fill in, and `a.fh-metric` opens its area. Key value list (`src/components/content/key-value.css`): `fh-kv` rows of label left, value right on dashed rules, two across from 38rem, `__full` for a long value; `--fields` puts a field beside each label (`--fh-kv-label`), `--single` keeps one column. No motion. Demos: section card and metric tiles on Admin (`/admin/`), key value list on Content (`#c-kv`).
- **Row spacing (`data-fh-rows`, KVL-2).** One setting for the room above and below every row of a table (`fh-table`), datatable (`fh-dt`), key value list and description list: `sm`, `md` (default, as before), `lg`, `xl`, as a preset in `fh.config` (so themes can pick it) that sets `--fh-row-pad`. `firehorse.js` wires `[data-fh-rows-select]` radios or selects: sets `data-fh-rows` on `<html>` (or `data-fh-rows-target`), remembers it in `localStorage["fh-rows"]`, fires `fh:rows`; `Firehorse.setRows()`. An admin page puts the switch in its toolbar and every table on it follows.
- **Spread metric tile (MET-1.5).** `fh-metric--spread`: label and description at the top, a wide gap (`--fh-metric-gap`, 3rem), then the value, progress and source at the bottom; tiles in a row line up at both ends. `__row` holds avatars (`fh-avatars`, square avatars), cubes and chips (MET-1.6); a cube, avatar or chip last in `__label` sits at the far right. `__more` (MET-1.7) is a `<details>` on an etched line with a chevron at the right: open, the tile grows in place and shows its detail, a key value list or a table, so the chevron stays under the pointer (use `--full` when the detail needs room); the chevron turns only when motion is allowed.
- **Metric deltas and charts.** `fh-metric__delta` with `data-trend="up|down|flat"` (arrow and success/danger colour) and `data-good="down"` to flip the colours where down is good (MET-1.8, 1.9); `__figure` puts value and delta on one line, the delta centred on the value, with avatars or a sparkline there pushed to the far right so every tile keeps one figure line; an `fh-sparkline` (MET-1.10), `fh-ring` or `fh-gauge` (MET-1.11) sits in a tile as it is. After Retool's Statistic, with the inverse trend it lacks.
- **Items share one build (HIG · Spacing · Items).** Menu items, native select options and the picker, entity picker options, segmented options, the environment pill and text fields all pad `--fh-item-block` (8px) by `--fh-item-inline` (12px), with `--fh-item-gap` (8px) between icon and text, in a `--fh-item-frame` (4px) frame, so a menu and a selector read as one family.
- **One card edge for the whole system.** Metric tiles, section cards, the masthead, table frames and the floating drawer take their edge from the card preset (`--fh-card-border-style`, `--fh-card-border-color`), so they are etched by default and follow the theme's `config.card` (or `data-fh-card`) like `fh-card` does: etched, solid, outline and the rest.
- **Type sizes meet the HIG.** Body text is 16px (`--fh-text-body`, was 15.2), labels and the small mono lines 11px (`--fh-text-label`, `--fh-text-micro`, were 10.9 and 9.9); 34 hard-coded sizes under 11px move to `--fh-text-micro`. Lint fails on any font size under 11px.
- **Rascode HIG chapters 2–9.** Type, color, lines, surfaces, motion, density, accessibility and naming on the Guidelines page, each with its rules, where Firehorse stands against them, and the references behind them.
- **Frame (HIG).** Apps use the site's page margin for their content line (`--fh-app-pad` is now `--fh-inset-page`: 20px phone, 50px desktop), and the sidebar's text sits 16px from the edge (a 4px frame plus each item's 12px). Section heads on Admin, Finance, Guidelines and References start on the page line. A Frame section on the Guidelines page.
- **References (`/references/`, `references.json`).** The 90 sources behind the Rascode HIG: 42 published design systems (14 Apple HIG pages, Material, Carbon, Fluent, Polaris, Atlassian, SLDS, Spectrum, GOV.UK, USWDS, Primer, Ant), 29 standards (WCAG 2.2, ARIA Authoring Practices, CSS Working Group specs, WAI tutorials, Design Tokens format), 9 practice and 10 usability research. Grouped by kind, indexed by chapter, generated from the platform's reference schema (`pnpm db seed:references --export`). Guidelines cite them under each rule.
- **Rascode HIG (`/guidelines/`), chapter 1: spacing by relationship.** Rascode's Human Interface Guidelines, which Firehorse and every design system Rascode publishes follow. Six gap tokens in the semantic layer (`--fh-gap-bound` 4px, `-related` 8, `-grouped` 12, `-grouped-wide` 16, `-sectioned` 24, `-separated` 48) and five insets (`--fh-inset-tight` 8, `-control` 12, `-tile` 16, `-card` 24, `-page`), re-resolved under `data-fh-density`. Seven rules with their reasons: inside tighter than outside, padding at least the gap, a rule replaces space, one gap per relationship, numbers line up, one left edge in a tile or card (indent only where a row has a leading column), no odd steps. Lint fails on a raw `--fh-space-*` in a component (`--loose-spacing` warns with a count instead). Every component is migrated: 909 raw uses moved to relationship tokens. Admin pieces (record, masthead, section card, metric tiles, gauge) and the key value list are migrated; odd steps moved to the nearest relationship. A section card's foot drops its own rule after a key value list.
- **Lighter fields in light scheme.** `--fh-color-field` is now the lightest grey (`--fh-gray-50`, was 150) and its hover `--fh-gray-100`, so inputs read on white without weight. Dark is unchanged. Entered values are a touch heavier (medium) and 3% larger than body text; placeholders stay at body weight.
- **Spread tiles (MET-2).** The spread tile's title is bold and full-strength, its figure a step heavier, and every part has a fixed row (label, description, gap, figure, chart or progress or people, source, detail) shared across tiles in `fh-metrics` through subgrid, so figures, charts and sources line up across a row whatever each tile carries: progress (MET-2.1), trend (2.2), sparkline (2.3), people (2.4), detail (2.6). New modifiers: `fh-metric--tinted`, a stronger tone wash with a tone edge for the tile that leads a row (2.5); `fh-metric--wide`, two columns (2.7); `fh-metric--full`, the full width of the row, with a table or key value list in a tile filling it edge to edge (2.8).
- **Gauge (GAU)**, `src/admin/gauge.css`: a half-circle meter from `--fh-value` (0–100), figure under the arc, caption below, arc in the tone; animates the value only when motion is allowed. Knobs `--fh-gauge-size`, `--fh-gauge-width`. Demo on Admin.
- **Backdrop (BKD)**, `src/admin/backdrop.css`: a quiet abstract picture behind a whole app, edge to edge: blurred tone fields under the sign-in page's etched contours at 6%. Fixed to the viewport; inside an `fh-app` with a backdrop the sidebar and top bar turn to glass. Knobs `--fh-backdrop-strength`, `--fh-backdrop-art`. Demo on Admin.
- **Frost (`--fh-frost`).** A theme token from 0 (clear glass) to 1 (nearly solid), default 0.6, that sets how much glass over a backdrop clouds and blurs: panels, tables, cards, the sidebar and the masthead in an `fh-app` with a backdrop, and anything with `.fh-frost`. `--fh-frost-fill` and `--fh-frost-filter` are ready-made for app pieces of your own. `firehorse.js` wires `<input type="range" data-fh-frost-select>` (0–100), remembers it in `localStorage["fh-frost"]`, fires `fh:frost`; `Firehorse.setFrost()`. Themes set it in their `tokens`.
- **Floating detail drawer.** `fh-dialog--float` now has an etched edge, floats `--fh-float-gap` (a new theme token, 0.75rem) from the screen edge, and eases in and out (`--fh-ease-in-out`, opacity and slide) over `--fh-float-duration`; reduced motion shows it without sliding.
- **Masthead (MST)**, `src/admin/masthead.css`: a glass header with the stacking deck's caption (`__index` left in the tone, `__title` right, an etched grey rule under both) on an etched, see-through panel that blurs what is behind it; `__foot` carries `__meta` and `__tools`. `--bar` is the one-line, sticky, pill-shaped top bar for an app, with no rule and an optional round mark first (`__mark`, the client's logo on an `fh-avatar--circle`). Knobs `--fh-masthead-fill` (62%), `--fh-masthead-blur`. Demo on Admin.
- **Record header (REC), with a cover.** The record header gets an Index ID and a demo on Admin. `fh-record--cover` with `fh-record__cover` adds a band across the top of the record header: a picture with a light scrim, or etched tone art when there is none. The eyebrow sits on the band and the mark overlaps its lower edge. Knob `--fh-record-cover` (11rem). Sample: `business-concept.html`.
- **Home screen wallpapers (WAL).** `fh-canvas--wall` draws a wallpaper on the phone's own icon grid: the brand on icon row 1, the page title on row 2, an etched rule with a tone tick under column 1, then a dashed cell where each icon lands (`fh-canvas__cells`) and the dock (`fh-canvas__dock`). Flat fill, no glow or frame. Presets in native pixels: `--wall-iphone` (17, 17 Pro, 18 Pro), `--wall-iphone-61` (15, 16), `--wall-iphone-air`, `--wall-iphone-max` (17/18 Pro Max), `--wall-pixel`, `--wall-pixel-xl`, `--wall-galaxy` (S26, S25) and `--wall-galaxy-qhd` (Plus, Ultra); `--wall-5x5` for the denser Android grid, `--wall-clean` for the title band alone. Grid positions are estimates until measured on each device; each preset is a handful of `--fh-wall-*` numbers to correct. `templates/wallpapers.html` sets one wallpaper per Focus per device for `npx firehorse-export`, whose capture viewport now fits a 3120 px-tall screen.
- **Index IDs by family, group and variant.** Every variant ID is now `FAM-G.V`: the number before the dot is a group of related variants, so siblings read together (`EYE-5.1` indexed, `EYE-5.2` segmented and `EYE-5.3` counted are the eyebrow pill's parts; `EYE-5` is the group). Avatars are one family (`AVT-1`…`AVT-5`, from `AVS AVZ AVR AVG AVK`), cube cards joined cubes (`CUB-2`, from `CUC`), chip cards joined chips (`CHP-3`, from `CHC`), and `MRK-01` (a second eyebrow pill) is retired in favour of `EYE`. Groups are named in the docs with `data-fh-groups` or by a demo or row carrying the group ID. The catalog runs by its groups. Every old ID is retired in the ledger and forwards to its replacement: links (`#EYE-18` lands on `EYE-5.2`), KC, `index.json` (`moved`) and a Former IDs table in `agent/index.md`.
- **Design-system reference.** Pages declare what they're built on: `<meta name="design-system" content="firehorse@1.1.0">` and `<link rel="design-system" href="https://firehorse.rascode.dev/index.json">` (the docs site does, and `agent/system.md` requires it). `index.json` carries a `system` block (key, name, version, class prefix, reference attribute, index URL), so audits work for any design system that publishes one.
- **`data-fh` on shipped markup.** Copied markup (site, `agent/index.md`, `agent/components.md`, `index.json`) carries `data-fh="<ID>"` on each component root, and the React components render it. Custom blocks take `data-fh="local:<name>"`.
- **`npx firehorse-audit`.** Audits built HTML, a folder or a URL against the Index: connected coverage, untagged roots with the ID their classes point to (`--fix` writes them), tags that disagree with their classes, retired and unknown IDs, elements not connected to Firehorse, repeated custom blocks and widely used `local:` components as candidates for new components, and Firehorse classes the Index has no ID for yet. `--json`, `--strict` and `--min` for CI and agents; `--crawl <n>` reads a deployed site (sitemap first, never sign-out or delete links), `--header` signs in to an internal one, and `--report md` prints the action report: every finding as an action for the app or for Firehorse, ordered now, next, later. Part of `npm test`.

- **Phone fixes.** The header's brand column can shrink (`min-inline-size: 0`), so a long brand never pushes the menu button off-screen; on the docs site the version tag drops its "Premium design system" segment under 25rem. The segmented switch (CHO) no longer turns vertical in any slot under 22rem: it stays a row down to 12rem, and `fh-segmented--stack` stacks it on purpose. The playground's Hero block now uses the documented hero markup (`fh-section--hero` > `fh-hero`), which fixes a headline that collapsed to one letter per line; on phones the playground is a read-only preview at phone width with a note to build on a larger screen.
- **Flat button (BTN-1.5).** `fh-button--flat`: solid black with white text in every scheme and theme, no sheen, shadow or press. Backed by two new semantic tokens, `--fh-color-ink` and `--fh-color-on-ink`. A `<code>` inside any button keeps its case, so a command reads as typed. The docs header now carries a flat `npm i @rascode/firehorse` copy button left of Download from Git; the hero install bar is gone.
- **Themes.** A theme is every design decision in one file: type, color in light and dark, radius, density, and the avatar, card, card-media, button, chip and table styles. Apply it with `data-fh-theme` on `<html>`. The `data-fh-*` presets remain as local overrides on a section.
- **Three built-in themes, named after breeds.** `mustang` (compact, square avatars, solid cards, flat buttons, zebra tables; slate and denim, condensed display), `friesian` (monochrome, square corners, outline cards, sharp buttons, underline chips, spacious; serif display), `akhal-teke` (soft corners, tonal cards, flat pill buttons, squircle avatars, borderless tables; sand and gold). `firehorse` restores the base inside a themed page. `dist/themes.css` bundles them; `dist/themes.json` lists them.
- **Theme compiler.** Themes are JSON (`src/themes/*.json`, template in `_template.json`). `scripts/gen-themes.mjs`, shipped as `npx firehorse-theme <file>.json`, expands `config` from the same presets the attributes use, tints the neutral ramp from a hue and chroma, re-derives semantic roles against the theme's palette, and fails if text, accent or on-accent drops below AA in either scheme. The build runs it.
- **Theme select.** `firehorse.js` wires any `[data-fh-theme-select]` select or radio: switches `data-fh-theme` (on `<html>` or `data-fh-theme-target`), keeps every picker in sync, remembers the choice in `localStorage["fh-theme"]`, fires `fh:theme`, and exposes `Firehorse.setTheme()`. React: `ThemeSelect` and `useFirehorseTheme()`. Index ID `THS`.
- **Layers.** Config presets moved to a new `fh.config` layer above `fh.themes`, so a `data-fh-*` attribute on a section still overrides the active theme there. Adaptive color re-evaluates on `[data-fh-theme]`.
- **Site.** A theme drawer with a dropdown and self-previewing theme cards, a theme select in the header and the mobile menu, and a Themes section. The playground's presets pick a theme, and exports carry `data-fh-theme` and its stylesheet. The Stable follows the chosen theme. Forms carry campaign attribution (UTMs, first touch, placement, page) to Rascode admin.
- **Docs site, one page per category.** The single long page is now a home page plus Foundations, Layout, Components (a hub with Actions, Content, Navigation, Overlays & feedback and Avatars), Forms, Data, Commerce, Audio, Theming, Agents and Pro. Each page opens with a breadcrumb, one title and its counts, then a floating bar whose chips are the page's component families, labelled by Index ID, with scroll spy and the rolling section title. The Docs mega, mobile menu, footer, ⌘K and the home bar are generated from the pages, `/#id` links from before the split forward to their new page, `index.json` and `agent/index.md` link each family to its page, and the build fails on a dead `#link`. Adds `sitemap.xml` and a page list in `llms.txt`.
- **Figures follow the theme.** New `--fh-font-figure` token for big numbers (stat values, tier and large prices). It defaults to the display face, so a theme's numbers change with its headings; a theme JSON can set `font.figure` to pick its own.
- **Theme in the URL.** The site reads `?theme=<name>` and `?scheme=light|dark|auto` on load and remembers them, so a link can open the docs in a given look. Lipizzaner is in the header and menu theme selects.
- **Admin dock (ADM-DCK).** `.fh-app-dock` holds a page's working bar (a composer, filters) under the top bar: flat at rest, frosted edge to edge once it pins, like the rascode.dev dock. The admin sidebar no longer sticks once it wraps on top. The thread composer lost its shadow.
- **Datatable: sticky cells stay solid on striped rows.** The zebra stripe used to clear the sticky select column's background, so cells scrolled under it showed through. The stripe now lays over the surface.
- **Source split into modules.** The 20 multi-component files are now one file per component (150 modules) in folders that match the docs: actions, content, navigation, overlays, feedback, people, forms, data (with a datatable/ folder), commerce, audio and media (with a canvas/ folder); patterns and the admin entry too. The manifests import them in the same cascade order, so the built CSS is unchanged. Each module opens with its name, Index ID and layer; each folder has a README.
- **Developer Portal** (`/developer/`). How the source is built (layers, manifests, bundle, checks), every module by folder with search by name, ID or class, a source viewer, the cascade order, what ships in dist with sizes, and how to add a module. Generated from src at build time.
- **Working indicator (ADM-WRK).** `fh-working` shows that an agent is on something: a thinking mark (a sparkle that turns and breathes, still under reduced motion), who, and what on. `fh-working__mark` alone marks a row or cell.
- **Entity picker (ENT).** A field whose value is an account, person or client. `fh-entity-picker` holds a trigger and a popover list built from the same row, `fh-entity`: an avatar, an etched separator (`fh-entity__sep`), the name and a second line (`fh-entity__who`), a stat (`fh-entity__stat`, a figure over a mono label, or `--count` for a toned counter), then the chevron. The list groups its options (`fh-entity-picker__group` with a legend), and every option is the same row as the selection, with a check on the chosen one. Shapes: field (default), `--rounded` and `--etched`; leave out the avatar and separator for a text-only picker. The options are real radios, so the value submits and arrow keys work with no script; `firehorse.js` mirrors the pick into the trigger, closes the list and fires `fh:entity`. React: `EntityPicker` with `entities`, `groupBy`, `shape`, `avatar` and a configurable `stat` (`{ label, value: (entity) => …, tone }`), so one picker shows open actions, unread or a balance depending on where it is used. Knobs `--fh-entity-avatar`, `--fh-entity-radius`, `--fh-entity-list-width`.
- **Inline tag field.** `fh-tags--inline` drops the field chrome: its chips, then a small round plus (`fh-tags__add`) that opens room for one tag at a time. With no tags, a text-link button stands in.
- **Round buttons.** `fh-button--round` makes a button a circle when paired with `fh-button--icon` (or a pill otherwise), for a single-glyph action such as a plus.
- **Reveal on hover: profile and environment.** `fh-profile--reveal` shows only the avatar until hover, keyboard focus or an open menu, then extends to the full chip. `fh-env-pill` is the environment selector's trigger built from the segmented eyebrow pill (EYE-5.2): live dot and environment on the left, host on the right, a chevron to say it opens; at rest only the dot and environment show. Removed `fh-avatar--round` (same as `--circle`), `fh-dialog--bottom` (same as `fh-dialog--sheet-bottom`), a second `fh-dialog--sheet` that the sheet module fully overrode, and the unused admin thread. The offset-panel footer asks its frame, not the viewport, so lint passes clean.

- **Lipizzaner theme.** Haute école for interfaces: Geist Serif display (self-hosted on the site until it reaches Google Fonts), porcelain and midnight neutrals, imperial claret on light and champagne gold on dark, hairline cards, oval avatars, spacious.
