# Firehorse

**A dark-first, container-native CSS design system.**
Components size themselves to the box they're in, not the screen.

[firehorse.rascode.dev](https://firehorse.rascode.dev) · [Agent contract](agent/system.md) · [Component markup](agent/components.md) · [Design library](https://design.rascode.dev)

```
npm i @rascode/firehorse
```

Firehorse is the system behind [rascode.dev](https://rascode.dev), extracted from production and rebuilt as a standalone package:

- **Container queries, not breakpoints.** Pages are frames, frames have slots, and every slot is a query container. Drop a card into a sidebar, a modal or a full-width grid and it lays itself out. The source contains zero viewport-width media queries, and the lint fails the build if one appears.
- **Cascade layers.** Eight layers, from `fh.reset` to `fh.utilities`. Any CSS you write outside a layer wins, so overrides never need `!important`.
- **`light-dark()` schemes.** Every color role is a light/dark pair. `data-fh-scheme="light"` flips a whole page or a single card.
- **Tones.** Nine category colors through one attribute: `data-tone="teal"`. Dots, marks, meta lines and links inside it follow.
- **Native HTML.** Accordions are `<details name>`, modals are `<dialog>`, menus are `[popover]`. No JavaScript.
- **Accessible by default.** Every text role passes WCAG AA in both schemes, checked on every build. Visible focus everywhere, motion opt-in, forced-colors support.
- **Agent-ready.** `agent/system.md`, `agent/components.md`, `llms.txt` and `tokens.json` let a coding agent build on-system the first time.

About 12 KB gzipped. MIT.

## Quick start

```html
<link rel="stylesheet" href="https://firehorse.rascode.dev/firehorse.css">

<div class="fh-page">
  <main class="fh-main">
    <section class="fh-section fh-section--hero">
      <div class="fh-hero">
        <p class="fh-eyebrow-pill" data-tone="live"><span class="fh-dot fh-dot--live"></span>Now booking</p>
        <h1 class="fh-display">Build the foundation.</h1>
        <p class="fh-lede">Connect the systems. Activate your AI.</p>
        <div class="fh-hero__actions">
          <a class="fh-button" href="/contact">Discuss a project</a>
        </div>
      </div>
    </section>
  </main>
</div>
```

Through the Rascode design library (one import path per system, installable from GitHub):

```js
// npm i github:rascode/design
import "@rascode/design-system/firehorse";
import "@rascode/design-system/firehorse/themes/rascode.css";
```

With a bundler, directly:

```js
import "@rascode/firehorse";                  // dist/firehorse.css
import "@rascode/firehorse/themes.css";         // optional: Mustang, Friesian, Akhal-Teke
import "@rascode/firehorse/themes/rascode.css"; // optional brand layer
import { tokens } from "@rascode/firehorse/tokens";
```

## The Firehorse Index

Every component and variant has a stable ID, so people and agents can name
UI instead of describing it: `CHP` is the chip family, `CHP-03` is the filled
chip with an icon, `TIR` is pricing tiers. On the site, each demo shows its
ID; click it to copy the ID with its markup and a note for your agent.

- [agent/index.md](agent/index.md): every ID with its markup, for agents
- `@rascode/firehorse/index.json`: the same registry as JSON
- `index-ledger.json`: every ID ever issued. IDs are never reused; `npm test`
  fails if one disappears without being retired.
- KC, the Firehorse guide ([agent/kc.md](agent/kc.md)), turns a description
  ("a filled chip with an icon") into the ID.

IDs are declared in the docs markup with `data-fh-id` (family on the demo,
variants on each variant) and generated by `scripts/gen-index.mjs`.

## Motion

Firehorse ships a motion layer you opt into, built on the platform rather than a script:

- **Flip** — `<span class="fh-roll">` inside any link or button rolls its label on hover and focus.
- **Rollover heading** — `.fh-rollover` rolls to new text, up going forward and down going back; the floating bar's title follows the section in view.
- **Scroll-driven entrances and parallax** — `fh-reveal`, `fh-reveal-children`, `fh-parallax`, `fh-scroll-progress`, with no JavaScript.
- **Behaviour** — `firehorse.js` pauses loops in off-screen sections and makes in-page links land under the sticky chrome, fast on long pages.

Everything respects `prefers-reduced-motion`, and nothing animates layout.

## Architecture

```
src/
  firehorse.css          entry: declares layer order, imports everything
  tokens/primitives.css  raw values: grays, ember, tone hues, type, space, motion
  tokens/semantic.css    roles via light-dark(); @property registrations
  base/                  reset, element defaults, typography roles
  layout/frame.css       page / frame / section / bleed / ruled sections
  layout/primitives.css  stack, cluster, auto grid, split, reel
  components/            button, markers, content, disclosure, form, table, chrome
  patterns/              hero, section head, etched split, CTA band, window, letter
  themes/                theme definitions (*.json) and the CSS compiled from them; brand layers
  utilities/             tones, sr-only, reveal, container-aware visibility
```

**Token tiers.** Primitives (`--fh-gray-950`) feed semantic roles (`--fh-color-canvas`), which feed component knobs (`--fh-button-bg`). Components may only read semantic tokens, and the lint enforces it.

**Frames and slots.** `.fh-page`, `.fh-main`, `.fh-section` and `.fh-frame` share one grid:

```
[full-start] gutter [content-start] ≤1400px [content-end] gutter [full-end]
```

Direct children sit in `content` and become `fh-slot` query containers. `.fh-bleed` spans `full`. Components inside a slot use `@container` and `cqi` units, so they respond to the slot's width.

**Layout knobs don't leak.** `--fh-gap`, `--fh-grid-min`, `--fh-split` and the other layout knobs are registered with `@property { inherits: false }`, so a stack's gap never becomes the gap of a cluster nested inside it.

## Themes

A theme is every design decision in one file: type, color in light and dark, radius, density, and how avatars, cards, card media, buttons, chips and tables look. It replaces the old per-decision configuration attributes: pick a theme instead of seven settings.

```html
<link rel="stylesheet" href="firehorse.css">
<link rel="stylesheet" href="themes.css">   <!-- or one: themes/friesian.css -->
<html data-fh-theme="friesian">
```

| Theme | Character | Decisions |
| --- | --- | --- |
| *(none)* | Firehorse base: etched lines, ember on charcoal | rounded avatars, etched cards, convex buttons, dashed chips, comfortable, lined tables |
| `mustang` | Bred on open range, built for work: slate and denim, condensed display | square avatars, solid cards, flat buttons, solid chips, compact, zebra tables |
| `friesian` | Jet black, feathered, formal: monochrome, serif display | circle avatars, outline cards, sharp buttons, underline chips, sharp corners, spacious, lined tables |
| `akhal-teke` | The golden horse of the desert: sand and burnished gold, humanist sans | squircle avatars, tonal cards, flat pill buttons, soft chips, soft corners, borderless tables |

Every theme ships light and dark; `data-fh-scheme` still chooses. `data-fh-theme="firehorse"` restores the base inside a themed page.

**Switching.** Any control with `data-fh-theme-select` switches the theme when `firehorse.js` is loaded, keeps other theme controls in sync and remembers the choice (`localStorage["fh-theme"]`). It fires `fh:theme` with `{ theme, previous }`; from script, `Firehorse.setTheme("mustang")`. Add `data-fh-theme-target="#preview"` to theme one element instead of `<html>`.

```html
<select class="fh-select" data-fh-theme-select aria-label="Theme">
  <option value="">Firehorse</option>
  <option value="mustang">Mustang</option>
  <option value="friesian">Friesian</option>
  <option value="akhal-teke">Akhal-Teke</option>
</select>
```

To avoid a flash of the default theme, restore it in `<head>`:

```html
<script>try{var t=localStorage.getItem("fh-theme");if(t!==null)t?document.documentElement.setAttribute("data-fh-theme",t):document.documentElement.removeAttribute("data-fh-theme")}catch(e){}</script>
```

React: `<ThemeSelect />` and `useFirehorseTheme()` in `@rascode/firehorse-react`.

**Make your own.** Start from `src/themes/_template.json`:

```json
{
  "name": "appaloosa",
  "label": "Appaloosa",
  "config": { "avatar": "circle", "card": "outline", "button": "flat", "chip": "solid", "radius": "soft", "density": "compact", "table": "zebra" },
  "color": {
    "neutral": { "hue": 250, "chroma": 0.012 },
    "accent": { "light": "#1d4ed8", "dark": "#60a5fa" },
    "onAccent": { "light": "#ffffff", "dark": "#0b1220" }
  },
  "font": { "display": "Georgia, serif" },
  "tokens": {}
}
```

```sh
npx firehorse-theme themes/appaloosa.json   # → themes/appaloosa.css
```

The compiler expands each `config` choice from the same presets the attributes use (`tokens/config.css`), tints the neutral ramp, re-derives every semantic role against the new palette, and fails if any text, accent or on-accent pair drops below WCAG AA in either scheme. `config` keys: `avatar`, `card`, `cardMedia`, `button`, `chip`, `radius`, `density`, `table`. `tokens` takes any other `--fh-*` value.

The `data-fh-*` presets still work as local overrides: they sit in the `fh.config` layer above `fh.themes`, so `<section data-fh-card="solid">` changes that section only.

### Brand layers

For a hand-written layer on top of a theme (fonts, a token or two), copy `src/themes/_template.css`, re-point tokens, and load it after the core:

```css
@layer fh.themes {
  [data-fh-theme="brand"] {
    --fh-font-sans: "Brand Sans", system-ui, sans-serif;
    --fh-color-accent: light-dark(#1d4ed8, #60a5fa);
    --fh-button-radius: var(--fh-radius-md);
  }
}
```

A theme never adds component selectors. If a brand needs a new component, it belongs in Firehorse.

## Structured data (Schema.org)

Mark components that hold real content with `data-schema`, then generate and check the JSON-LD:

```html
<div class="fh-accordion" data-schema="faq">…</div>
<nav class="fh-breadcrumb" data-schema="breadcrumb">…</nav>
<div class="fh-tiers" data-schema="offers" data-currency="USD">…</div>
```

```sh
npx firehorse-schema dist/index.html --write   # writes <script type="application/ld+json" id="fh-schema">
npx firehorse-schema dist/index.html           # CI: exits 1 if JSON-LD is invalid or doesn't match the page
```

Supported: `breadcrumb` → BreadcrumbList, `faq` → FAQPage, `offers` → Service + Offer, `service` → Service, `review` → Review, `howto` → HowTo, `person` → Person, `article` → Article. Hand-write one `Organization` with an `@id` in `<head>` and generated nodes link to it. Full mapping: [`schema/mappings.json`](schema/mappings.json) and [`agent/schema.md`](agent/schema.md).

## Development

```bash
npm install
npm test        # lint → build → verify (contrast + artifacts)
npm run build   # dist/
node scripts/agent-docs.mjs   # regenerate agent/components.md from the site demos
node scripts/site.mjs         # build site/dist for firehorse.rascode.dev
```

`npm run lint` fails on raw colors outside tokens, primitives used in components, viewport-width media queries, `!important` outside the reset, undefined custom properties, and classes without the `fh-` prefix.

## Browser support

The default build targets browsers with native nesting, `light-dark()`, `@starting-style` and container queries: Chrome/Edge 123+, Firefox 128+, Safari 17.5+. `compat.min.css` extends that to Chrome 108, Firefox 115 and Safari 16.4 by lowering nesting and `light-dark()`. A few enhancements (animated `<details>` height, customizable `<select>`, anchor-positioned menus, scroll-driven reveal) apply where supported and fall back cleanly.
