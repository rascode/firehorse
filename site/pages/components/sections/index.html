A section where a person edits the record in place: one form with one fieldset of Firehorse fields (fh-money included, and fh-panel-section__slot for a field the host supplies), then the actions row. A section whose slot holds a field that renders its own form uses <div class="fh-panel-section__form" role="group" aria-labelledby="…"> as its body instead of the form: never put a form inside a form. Report policy

660 words17 Nov 2026

How a relay report is written

A relay report is the record of one run. It names the relay, the worktree and the branch, then what was built and what each check printed. It is written once, when the run ends, and it does not carry a key. The person who reads it should be able to see the work without opening the branch.

The timetable is one line per step. Each line starts with the local time the step finished. The time comes from the clock, never from a guess. A step that is still running is not a finished line, and a time you did not read is not a time you may print.

House voice is plain. Say what the section holds and what a person can do with it. Leave out a claim you did not check. If a screen was not opened, say that the screen was not opened. A guess dressed up as a result is worse than a gap.

What goes in

Start with the run context as it was handed over. Then the timetable. Then the codes you issued, and the result of each check. End with the words the spec asks for. Do not add a second ending, and do not rewrite the context block.

Commands go in with a short view of their output. Trim a long log to the lines that show the result. If a command was not allowed, say so and do not invent a result. A skipped check is a result of its own: name it, and say why it was skipped.

A fix after a commit is a second commit. Nothing is amended, stashed, reset or pushed. The hook runs. A message names the kind and the spec, so a later reader can find the run from the history alone.

What stays out
  • No key, token or password, even when a check printed one.
  • No path outside the worktree, and no read of a file that holds a secret.
  • No claim that a test passed unless the output says it passed.
  • No second layout, and no colour, radius or shadow of your own.
  • No retired code brought back, and no code renumbered to make a row fit.
  • No part from outside Firehorse. If a part is missing, stop and say so.
How the checks read

Read the result from the command, not from memory. A line that says skip is expected when the diff does not touch what that check reads. Do not run a skipped check by hand to fill the report. The sweep runs the wide checks once per wave.

The screen tier checks the page. At a narrow width the page itself does not scroll sideways: a long line of code, and a deep tree, scroll inside the section. The report says so only after a check, or it says the check was not run.

The same rules apply to a policy, a long reply and a spec. Past about 24 lines the text folds, and Show all opens it in place. A short note does not fold. Headings step down so they sit under the section title, in the prose roles.

Chips show only while the section is closed. For a document they are the word count and the date it was updated. The count is the words in the body, including the headings, the table and the code.

How a relay report is written

A relay report is the record of one run. It names the relay, the worktree and the branch, then what was built and what each check printed. It is written once, when the run ends, and it does not carry a key. The person who reads it should be able to see the work without opening the branch.

The timetable is one line per step. Each line starts with the local time the step finished. The time comes from the clock, never from a guess. A step that is still running is not a finished line, and a time you did not read is not a time you may print.

House voice is plain. Say what the section holds and what a person can do with it. Leave out a claim you did not check. If a screen was not opened, say that the screen was not opened. A guess dressed up as a result is worse than a gap.

What goes in

Start with the run context as it was handed over. Then the timetable. Then the codes you issued, and the result of each check. End with the words the spec asks for. Do not add a second ending, and do not rewrite the context block.

Commands go in with a short view of their output. Trim a long log to the lines that show the result. If a command was not allowed, say so and do not invent a result. A skipped check is a result of its own: name it, and say why it was skipped.

A fix after a commit is a second commit. Nothing is amended, stashed, reset or pushed. The hook runs. A message names the kind and the spec, so a later reader can find the run from the history alone.

What stays out
  • No key, token or password, even when a check printed one.
  • No path outside the worktree, and no read of a file that holds a secret.
  • No claim that a test passed unless the output says it passed.
  • No second layout, and no colour, radius or shadow of your own.
  • No retired code brought back, and no code renumbered to make a row fit.
  • No part from outside Firehorse. If a part is missing, stop and say so.
How the checks read

Read the result from the command, not from memory. A line that says skip is expected when the diff does not touch what that check reads. Do not run a skipped check by hand to fill the report. The sweep runs the wide checks once per wave.

The screen tier checks the page. At a narrow width the page itself does not scroll sideways: a long line of code, and a deep tree, scroll inside the section. The report says so only after a check, or it says the check was not run.

The same rules apply to a policy, a long reply and a spec. Past about 24 lines the text folds, and Show all opens it in place. A short note does not fold. Headings step down so they sit under the section title, in the prose roles.

Page templates

Five fixed layouts, fh-tpl--landing, list, detail, form and empty, placed in the page's fh-main. A page picks one and fills its regions with Firehorse parts; it never sets its own layout. Spacing between regions is one step on every template, and each template responds to its own width, so every one holds at 1440 and at 375. Page templates use the record header and section card, which ship in firehorse.css.

Chip rules

Three markers, three jobs. fh-chip with data-status is the one chip for the status of a record, and its tone follows the status value. fh-badge is for counts only. fh-status is inline status text only. Chips live in the record header, in a collapsed section's summary and once per row (status only), and nowhere else in a body.
