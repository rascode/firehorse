01Why

Theproblem

Every team ends up rebuilding the same buttons, forms and layouts. Colours drift, spacing becomes guesswork, accessibility gets bolted on late, and the agents now writing much of the interface have nothing consistent to build from. The product looks a little different on every page, and each change costs more than the last.

  • DriftNear-identical colours, sizes and spacings multiply
  • ReworkEvery feature restyles the basics from scratch
  • GuessworkAgents invent their own UI, page by page

How02

Thesolution

Firehorse is one shared language for people and agents: tokens, components and design patterns, written as plain fh-* classes with no JavaScript required. Change a root colour and the whole system follows. Hand an agent llms.txt and it builds on-system the first time.

  • TokensOne source for colour, type and space
  • ComponentsParts and design patterns, ready to use
  • Agent-readyllms.txt and prompts, built in

Firehorse is configured, not coded. A root colour, a typeface and a density are written once, as tokens and a few data attributes, and every component reads from them. Change the configuration and the code underneath follows everywhere at once, connected through the cascade. Nothing is styled twice, so your code stays DRY, and nothing asks you to decide twice, so it doesn't make you think.
