How it’s built

Layers decide what wins; modules decide where things live. Every number on this page is counted from src/ when the site builds.

Layers, lowest first

Every rule lives in a cascade layer, so order between layers is fixed and anything you write outside a layer wins without !important. Inside a layer, a later module wins a tie with an earlier one.

How a stylesheet is made

  1. Modules

    One file per component under src/, native nesting, tokens only. Each opens with its name, Index ID and layer.

  2. Manifests

    src/firehorse.css imports every module in cascade order.

  3. Bundle

    scripts/build.mjs bundles each manifest with Lightning CSS into dist/: readable, minified and a compat build.

  4. Checks

    scripts/lint.mjs holds the rules (tokens only, no viewport queries, fh- prefix); the Index check keeps every ID on the docs.

Cascade order

The order the manifests import the modules. Within a layer it decides ties, so a new module goes where it belongs in this list, not at the end.

What ships

The files in dist/. Import one bundle; the modules are for reading and contributing, not for importing piecemeal.

Add a module

Every component follows the same five steps, so the source, the docs and the Index stay in step.

  1. Write the file

    One component per file in its category folder, opening with /* Firehorse — Name (ID) */, all rules inside @layer fh.components, tokens only.

  2. Import it

    Add an @import to src/firehorse.css next to the components it relates to.

  3. Demo it

    Add a demo to its docs page with a data-fh-id, and issue the ID in index-ledger.json.

  4. Check it

    npm run build, then node scripts/lint.mjs and node scripts/gen-index.mjs --check.

  5. Note it

    Add a line to CHANGELOG.md. This portal picks the module up on the next site build.
