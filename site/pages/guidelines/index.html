HIG · 01

Spacing by relationship

The Rascode HIG holds for Firehorse and every design system Rascode publishes; each system maps these relationships onto its own tokens. Space says how things relate. A component never picks a number; it picks a relationship, and the relationship has one size everywhere. That is why a figure and its source line sit 4px apart on every tile, in every product.

The six steps

Gaps between things. Each is a token in the semantic layer, mapped onto the spacing ramp, so themes and data-fh-density scale every relationship together.

Sources. A 4px base on an 8px rhythm is what Material, Carbon, Fluent, Atlassian, USWDS and Polaris all ship; named steps (not raw numbers) is how Carbon, Atlassian and USWDS publish them. Material Design 3: Grids and spacing · Carbon Design System: Spacing · Fluent 2 Design System: Layout · Atlassian Design System: Spacing · U.S. Web Design System: Spacing units · Shopify App Design Guidelines: Layout · 8-Point Grid

--fh-gap-bound
4px · Parts of one fact. A figure and its source line, a label and its value, an icon and its text.
--fh-gap-related
8px · Things that belong together. A figure and its chart or bar, chips in a row, a field label and its input.
--fh-gap-grouped
12px · Siblings. Tiles in a grid, rows in a list, fields in a form.
--fh-gap-grouped-wide
16px · Siblings that need air. Cards in a column, form rows.
--fh-gap-sectioned
24px · Parts of a card or panel. Head, body and foot of a section card; card padding.
--fh-gap-separated
48px · Sections on a page. One section card to the next, page bands.

The rules

Seven rules, each with the reason behind it.

Sources. Tighter inside than between groups (NN/g, Ant, Spectrum); the parent owns the gap (CSS Box Alignment, Every Layout); containers and space group before rules do (NN/g, Fluent). Proximity Principle in Visual Design · Ant Design: Proximity · Spectrum: Spacing · CSS Box Alignment Module Level 3 · Every Layout · The Principle of Common Region: Containers Create Groupings · Fluent 2 Design System: Layout · Refactoring UI

  1. Inside is tighter than outside. The space inside a thing is smaller than the space around it. That is how the eye knows where one thing ends.
  2. Padding is at least the gap. A container's padding is at least as large as the gap between its children, or the children look like they spill out.
  3. A rule replaces space. An etched rule stands in for a gap; it never adds one. Two rules in a row, or a rule plus a gap, reads as a mistake.
  4. One gap per relationship. Space comes from the parent's gap, not from stacked margins, so it can't double up.
  5. Numbers line up. Tiles in a row share rows, so every figure sits at the same height whatever the tile carries.
  6. One left edge in a tile or card. Title, description, figure and source all start at the same edge; an icon or cube sits inline in the title, not in a column of its own. Indent only where a row has a leading column (an avatar or icon in a list row, picker or menu item): there, text aligns with text.
  7. No odd steps. 2px, 6px, 10px, 14px, 20px and 28px are not relationships. Each moves to the nearest step, or the reason is written beside it.

Items: menus and selectors

A menu item, a select option, a picker option and a segmented option are the same thing, so they are built the same way: --fh-item-block 8px by --fh-item-inline 12px, --fh-item-gap 8px between icon and text, inside a --fh-item-frame of 4px. Text fields use the same padding, so a field and its menu line up.

Sources. Targets at least 24px, aiming for 44pt (WCAG 2.2, Apple); menus, listboxes and radio groups are one family of patterns (ARIA APG). WCAG 2.2 SC 2.5.8: Target Size (Minimum) · Apple HIG: Buttons · ARIA APG: Menu and Menubar Pattern · ARIA APG: Listbox Pattern · ARIA APG: Radio Group Pattern · Apple HIG: Menus · Apple HIG: Segmented controls · Touch Targets on Touchscreens

Scheme

Frame

One page margin, --fh-inset-page (20px on a phone, 50px on a desktop), from the viewport edge to the content line. On a site the header, every section and the footer start on it. In an app the content line sits one page margin from the sidebar, and the top bar, page header, cards and tables start on it. The sidebar's text sits 16px from the edge: a 4px frame plus each item's 12px. Full-bleed bands run past the line; cards and tables sit on it.

Held by lint

npm run lint flags any raw --fh-space-* in a component and prints the count. It is an error: the build fails on a raw step. --loose-spacing turns it back into a warning with a count, for a source tree still moving over. Tokens, themes and the layout primitives are exempt.

HIG · 02

Type

Text people can read at any size.

Rules

Where Firehorse stands. Body is 15.2px (--fh-text-body), labels 10.9px and micro 9.9px: below these rules. Moving them is the next type change.

Sources. Apple HIG: Typography · GOV.UK Design System: Type scale · Butterick's Practical Typography: Summary of key rules · The Elements of Typographic Style · WCAG 2.2 SC 1.4.12: Text Spacing · Primer: Text resizing and spacing · Utopia: fluid type and space · Material Design 3: Applying type

  1. Body text is at least 16px on reading surfaces. Apple, GOV.UK and Butterick land between 16 and 19px for body copy; below that, reading slows.
  2. UI text is never under 11px. Apple sets 11pt as the floor for any text; labels and captions stop there.
  3. Lines run 45 to 90 characters. The measure where the eye finds the next line without effort (Butterick, Bringhurst).
  4. Layouts survive text spacing and 200% zoom. WCAG 1.4.12 and 1.4.4: a reader can widen spacing or enlarge text and nothing clips or overlaps.
  5. Figures use the figure font with tabular numbers. Columns of numbers line up digit for digit.

HIG · 03

Color

Color says what something is, never only what it looks like.

Rules

Where Firehorse stands. npm run verify checks 64 text pairs at AA in both schemes. Field fills on white are deliberately faint; a field is found by its label and focus ring, and its focus ring holds 3:1.

Sources. WCAG 2.2 SC 1.4.3: Contrast (Minimum) · WCAG 2.2 SC 1.4.11: Non-text Contrast · Apple HIG: Color · Material Design 3: Color roles · CSS Color Module Level 5 · CSS Color Module Level 4 · Atlassian Design System: Design tokens · Refactoring UI

  1. Text holds 4.5:1 against its background, large text 3:1. WCAG 1.4.3, in both schemes.
  2. Controls and the edges that identify them hold 3:1. WCAG 1.4.11: a reader must be able to find the button or the field.
  3. Colors are named by role, not hue. Text, surface, etch, tone; light and dark come from light-dark() on the same name (Apple semantic colors, Material roles, CSS Color 5).
  4. One accent per view. Tones carry category; rules stay grey. The number carries the color; lines and frames do not compete with it.
  5. Meaning never rides on color alone. A status has a word or an icon as well as a tone.

HIG · 04

Lines

A line is structure, drawn only where space can't do the job.

Rules

Where Firehorse stands. Card, tile, table and drawer edges follow the theme's card preset (etched by default).

Sources. WCAG 2.2 SC 2.4.13: Focus Appearance · WCAG 2.2 SC 1.4.11: Non-text Contrast · The Principle of Common Region: Containers Create Groupings · Fluent 2 Design System: Layout · Apple HIG: Lists and tables

  1. Etched, dashed rules mark structure. The Firehorse line: rows, card edges, a section foot.
  2. A rule replaces space; it never adds to it. See Spacing, rule 3.
  3. Containers group before rules divide. A shared edge or fill groups content more strongly than a divider (NN/g common region, Fluent).
  4. Focus is a solid ring at least 2px wide, 3:1 against what's around it. WCAG 2.4.13; never removed, never dashed.

HIG · 05

Surfaces

Few levels, each with a job.

Rules

Where Firehorse stands. Frost, backdrop and the floating drawer follow these; the drawer uses the native <dialog>.

Sources. Apple HIG: Materials · Apple HIG: Sheets · Material Design 3: Elevation · Fluent 2 Design System: Elevation · ARIA APG: Dialog (Modal) Pattern · The Principle of Common Region: Containers Create Groupings

  1. Canvas, surface, raised, overlay: four levels, no more. A small fixed set of elevations (Material, Fluent) keeps depth readable.
  2. Glass is for chrome and controls, not for content. Apple materials: bars, sheets and panels frost; reading surfaces stay solid enough to read.
  3. How much glass clouds is one theme setting. --fh-frost, 0 to 1.
  4. A sheet or dialog takes focus and gives it back. ARIA APG dialog: focus moves in, Escape closes, focus returns to what opened it.

HIG · 06

Motion

Motion explains a change; it never decorates one.

Rules

Where Firehorse stands. Durations and easings are tokens (--fh-duration-*, --fh-ease-*); every animation sits inside prefers-reduced-motion: no-preference.

Sources. Apple HIG: Motion · Material Design 3: Easing and duration · Carbon Design System: Motion · Fluent 2 Design System: Motion · Executing UX Animations: Duration and Motion Characteristics · CSS Easing Functions Level 1 · Media Queries Level 5 · WCAG Technique C39: Using the CSS prefers-reduced-motion query to prevent motion

  1. 100 to 500ms. Fast (150ms) for small things, base (220ms) for most, slow (420ms) for sheets and panels.
  2. Ease out to arrive, ease in and out to move. Things that enter decelerate; things that travel accelerate and settle (Material, Carbon, Fluent).
  3. Reduced motion removes it. Under prefers-reduced-motion: reduce nothing slides, pulses or rolls; state changes appear at once (WCAG technique C39, Media Queries 5).
  4. Nothing moves under the pointer. A control that opens stays where it was clicked, so closing is the same click.

HIG · 07

Density

Dense or roomy, the relationships hold.

Rules

Where Firehorse stands. Row spacing S, M, L, XL is one switch for every table and key value list.

Sources. WCAG 2.2 SC 2.5.8: Target Size (Minimum) · WCAG 2.2 SC 2.5.5: Target Size (Enhanced) · Touch Targets on Touchscreens · New Density Settings for the Lightning Experience UI · Spectrum: Spacing · Shopify App Design Guidelines: Layout

  1. Targets are at least 24px; aim for 44 on touch. WCAG 2.5.8 is the floor, Apple's 44pt the goal.
  2. Density scales every relationship together. data-fh-density rescales the spacing steps; data-fh-rows sets row spacing for every table at once.
  3. Compact never goes below the target minimum. Rows tighten; hit areas don't.

HIG · 08

Accessibility

WCAG 2.2 AA is the floor, not the goal.

Rules

Where Firehorse stands. Segmented controls are real radios; expanding tiles are <details>; the drawer is <dialog>.

Sources. Web Content Accessibility Guidelines (WCAG) 2.2 · WCAG 2.2 SC 1.4.10: Reflow · ARIA APG: Menu and Menubar Pattern · ARIA APG: Listbox Pattern · ARIA APG: Combobox Pattern · ARIA APG: Radio Group Pattern · ARIA APG: Disclosure (Show/Hide) Pattern · Apple HIG: Accessibility

  1. Everything works with a keyboard, in the order it reads. The ARIA Authoring Practices patterns for menus, listboxes, comboboxes, dialogs, disclosures and radio groups.
  2. Content reflows at 320px without scrolling sideways. WCAG 1.4.10; container queries, not breakpoints.
  3. Real elements first. A button is a <button>, a choice is a radio, a disclosure is <details>; ARIA only where HTML has nothing.

HIG · 09

Naming

A name says what a thing is, not where it was first used.

Rules

Where Firehorse stands. Firehorse ships tokens.json; the Index gives every component and variant a stable ID.

Sources. Design Tokens Format Module · Atlassian Design System: Design tokens · Material Design 3: Design tokens · Carbon Design System: Spacing · Atomic Design, Chapter 2: Atomic Design Methodology · Jakob's Law of Internet User Experience

  1. Components are named for what they are. Key value list, not property list; metric tile, not readiness card.
  2. Tokens are named by role and relationship. --fh-gap-bound, --fh-color-etch; never a number in a name that means a place.
  3. Tokens publish in the W3C Design Tokens format. So other tools and Rascode design systems can read them.
  4. Use-case names only when the owner asks for them. Generic first; a named variant is a decision, not a default.
