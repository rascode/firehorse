Why it fits

Nothing in Firehorse competes for the same names or the same place in the cascade as another system, as long as the layers are in order.

  1. Its own names

    Every class starts with fh- and every token with --fh-, so none collide with Tailwind's utilities, shadcn's classes or your own.

  2. Named layers

    All of Firehorse sits in one cascade layer, fh, with its parts inside it (fh.reset to fh.utilities). Where that layer sits decides whether Firehorse or the other system wins when both style the same thing.

  3. Live tokens

    The tokens are CSS custom properties that follow the Firehorse theme and the light or dark scheme. Any system that reads CSS variables can use them.

  4. No framework

    Menus, dialogs and accordions are native HTML (popover, dialog, details). Firehorse works in React, Vue, Svelte or plain HTML, and never fights a component library's JavaScript.

Tailwind CSS v4

Import Firehorse's Tailwind file first, then Tailwind. That's all.

  1. Layers in order

    Firehorse sits above Tailwind's preflight and below its components and utilities. So fh-button mt-6 takes the margin and fh-button rounded-none loses its corners: a utility on a Firehorse part always wins.

  2. Firehorse loaded

    The file loads firehorse.css for you. Its reset and document defaults replace preflight's where both set something.

  3. Tokens as utilities

    Tailwind gets the Firehorse tokens as theme values, prefixed fh- so they never clash with your palette: bg-fh-surface-raised, text-fh-muted, border-fh-etch, ring-fh-focus, font-fh-mono, rounded-fh-md. They are the live tokens, so changing the Firehorse theme or scheme restyles the utilities too.

Without this file, the order you import in decides the result. Firehorse after Tailwind keeps its components, but Tailwind utilities can't override them. Firehorse before Tailwind loses its components to preflight: buttons, fields and tiles lose their padding, borders and fills.

shadcn/ui

shadcn gives you React components with Radix behaviour; Firehorse gives you the design system underneath them. One import puts shadcn's components on the Firehorse theme.

  1. shadcn's variables on Firehorse tokens

    --primary is the Firehorse accent, --background the canvas, --card the raised surface, --muted-foreground the muted text, --border, --ring, --radius and the chart and sidebar colours follow. Change the Firehorse theme and every shadcn component follows it.

  2. Light and dark

    The page is light until .dark is set, as shadcn expects; .dark switches Firehorse to dark too. A data-fh-scheme attribute still wins where you set one.

  3. Both side by side

    Use shadcn components where you want their React behaviour and Firehorse parts everywhere else. They share one palette, one radius and one focus ring.

Bootstrap, MUI and the rest

The same rule applies: Firehorse's class names never collide, and the cascade decides who wins.

  1. CSS outside any layer wins

    Bootstrap's stylesheet and CSS-in-JS libraries such as MUI add CSS outside any layer, and that beats every Firehorse layer. To let Firehorse win, import the other stylesheet into a layer of its own before Firehorse's: @import "bootstrap.css" layer(vendor); with @layer vendor, fh; first.

  2. Read the tokens

    Point the other system's theme at --fh- tokens, as the shadcn file does, so both wear one theme.

  3. One reset

    If both systems ship a reset, put the one you want to keep in the later layer.
